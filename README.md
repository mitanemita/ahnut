# Ахнуть — «Открытка, от которой ахнут»

Сервис персональных ИИ-открыток в подарок. Этап 1 — скелет: Docker Compose, Caddy (HTTPS через
Let's Encrypt), Postgres, n8n, «hello world» сайта.

## Стек и почему он

- **Python 3.12 + FastAPI + Jinja2 + SQLAlchemy 2 (async) + Alembic + Postgres** — тот же стек, что
  во втором проекте (`dubrovskiy_arenda`): один набор привычек, команд и деплоя на двоих.
  Страницы рендерятся на сервере, интерактив анкеты на небольшом ванильном JS, без отдельного
  фронтенд-проекта и сборщика: меньше всего, что придётся поддерживать в одиночку.
- **Сборка открыток** (этап 3): Jinja-шаблоны блоков + JSON от нейросети → HTML. Самопроверка по
  скриншоту на 375px через Playwright для Python (добавим отдельным сервисом на этапе 3/6).
- **n8n** — конвейер генерации. Вебхук ЮKassa принимает `web`, проверяет платёж запросом к API
  ЮKassa и только после этого вызывает n8n внутри Docker-сети. Наружу n8n открыт лишь своим
  интерфейсом (`n8n.ahnut.ru`, вход по учётной записи владельца).
- **Caddy** — сам получает и продлевает сертификаты, конфиг на 20 строк.

## Сервисы (`docker-compose.yml`)

| Сервис | Что делает |
|---|---|
| `caddy` | 80/443, HTTPS, `www` и `ахнуть.рф` → редирект на `ahnut.ru` |
| `db` | Postgres 17; при первом старте создаёт отдельную базу `n8n` (`db/init/`) |
| `migrate` | `alembic upgrade head`, затем завершается |
| `web` | сайт; файлы фото/открыток лежат в `./data/files` на диске сервера |
| `n8n` | оркестратор, хранит данные в Postgres |

## Запуск на сервере

```bash
cp .env.example .env    # заполнить пароли: openssl rand -hex 24
./deploy.sh
```

До запуска в DNS нужны A-записи на IP сервера: `ahnut.ru`, `www.ahnut.ru`, `n8n.ahnut.ru`,
`ахнуть.рф`, `www.ахнуть.рф`. Без них Caddy не получит сертификаты.

Локально без доменов: в `.env` раскомментировать блок «Локальный запуск», открыть
`http://localhost` и `http://n8n.localhost`.
